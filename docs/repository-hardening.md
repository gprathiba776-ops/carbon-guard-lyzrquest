# Repository hardening

This pass addresses repository-level engineering findings separately from the CarbonGuard ESG control architecture.

## Implemented

- HTTP contract tests for both deterministic APIs.
- Expanded frontend governance/failure mapping tests.
- CI installs both backend service dependency sets.
- CI runs backend tests, frontend typecheck/tests/build, Docker builds and a tracked-secret scan.
- Repository static verification includes the API contract suite.
- A submission verification script runs the complete local quality sequence.
- Frontend dependency versions are exact and the package manager/runtime versions are declared.
- Dependabot covers npm, Python and GitHub Actions dependencies.

## Frontend lockfile

`frontend/package-lock.json` should be generated by npm on a network-enabled machine and committed to the repository. The execution environment used to prepare this archive cannot resolve `registry.npmjs.org`, so a synthetic lockfile is intentionally **not** checked in.

Generate the real lockfile with:

```bash
cd frontend
npm install --package-lock-only --ignore-scripts --no-audit --no-fund
cd ..
```

Then run:

```bash
./scripts/prepare_submission.sh
```

The CI workflow currently uses `npm install` because the lockfile must be generated from the authoritative npm registry before switching CI to `npm ci`.

This avoids claiming reproducibility from a hand-written or incomplete lockfile.
